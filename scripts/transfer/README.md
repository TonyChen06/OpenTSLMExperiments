# Ahri → OpenTSLM-SP Transfer Experiment

The "applicable benefit" argument for the paper: pretraining on Ahri
yields a measurable improvement on the downstream clinical tasks that
OpenTSLM-SP is actually trained on.

## Design

Sequential curriculum, matching Stanford's upstream `curriculum_learning.py`
recipe (the model trains through tasks in order; eval is reported after
each stage, before the next one starts).

| Run | Stages (in order) |
|---|---|
| **Control** | `Llama-3.2-1B → TSQA → HAR → Sleep` |
| **Treatment** | `Llama-3.2-1B → AHRI → TSQA → HAR → Sleep` |

Only difference between control and treatment: AHRI inserted as stage 0
in the treatment. Both train identically afterwards. Per-stage test
accuracy is compared. 2 runs total.

ECG-QA-CoT was dropped from the headline experiment because its 12-lead
× 1000-sample signals produce 3,000 patch tokens per example, making
per-step compute 22-68× heavier than the other stages — incompatible
with reasonable wall time on a 5 GB-budget GPU.

Trainable parameter set in both runs: encoder + projector + LoRA adapters
(r=16, α=32) on the LLM. Same trainable params, same hyperparams — only
the initialization differs.

## Pretrain corpus

The AHRI stage uses a separate **`pretrain` split** generated specifically
for this experiment:

- **3,000 examples per task** (half of the standard 6k training set size)
- **Full parameter range**, including held-out — train sees the entire
  waveform vocabulary, no exclusion
- **63,000 examples total** across all 21 tasks
- Generated by `python -m opentslm.ahri.generate` (the script writes
  `pretrain.parquet` alongside the existing `train/val/test.parquet`)

Train/val/test splits remain unchanged from the RQ1/RQ2 paper experiments.

## Hyperparameters

- **LLM**: `meta-llama/Llama-3.2-1B-Instruct` (bf16 frozen; LoRA adapts it)
- **Epochs**: 3 per stage (both AHRI and each downstream)
- **Batch**: 2
- **LR**: 1e-4, cosine with 5% warmup, AdamW wd=0.01, grad clip 1.0
- **LoRA**: r=16, α=32, dropout 0, targets q/k/v/o/gate/up/down
- **Patch size**: 4 (matches upstream OpenTSLM)

## Files

| File | Purpose |
|---|---|
| `src/opentslm/ahri/opentslm_adapter.py` | Ahri parquet → OpenTSLM-SP dict format (`AhriQADataset`, `ahri_all_tasks`). |
| `scripts/transfer/train_curriculum.py` | Sequential trainer; runs an ordered list of stages on one model. Resumable: stages with a `_final.pt` checkpoint are skipped. |
| `scripts/transfer/run_curriculum_experiment.sh` | Runs both control + treatment in parallel across two GPUs. |
| `scripts/transfer/compare_curriculum.py` | Per-stage delta table + verdict. |
| `tests/ahri/test_opentslm_adapter.py`, `test_pretrain_split.py` | 17 unit tests, no GPU needed. |

## Launching

```bash
# Defaults: Llama-3.2-1B-Instruct, 3 epochs/stage, batch 2, control on GPU 6 and treatment on GPU 7
bash scripts/transfer/run_curriculum_experiment.sh
```

The two runs go in parallel. Treatment takes longer because it has the
extra AHRI stage. Logs land in `logs/transfer/{control,treatment}.log`.

After both finish, comparison automatically runs and prints:

```
| Stage   | Control | Treatment | Δ (pp) | Verdict |
|---------|---------|-----------|--------|---------|
| har_cot |  X.X%   |  Y.Y%     |  +Δ    | ⬆/⬇/≈   |
| sleep   |  X.X%   |  Y.Y%     |  +Δ    | …       |
| ecg_qa  |  X.X%   |  Y.Y%     |  +Δ    | …       |

Headline verdict: PROMISING / MILD POSITIVE / NULL / HURTS
```

Resumable: re-running the same command skips stages whose `_final.pt`
already exists in the output dir.

## Dataset sizes and per-stage compute load

Measured after downloads + parsing.

| Stage | Train | Val | Test | Patches / example | seq_len through LLM |
|---|---|---|---|---|---|
| AHRI pretrain | 63,000 | — | — | ~304 (Tier 3 has 512) | ~300–560 |
| TSQA | 38,400 | 4,800 | 4,800 | ~64 (median signal 256 samples) | ~265 |
| HAR-CoT | 68,542 | 8,718 | 8,222 | 3 × 32 = **96** | ~400 |
| Sleep-EDF-CoT | 7,434 | 930 | 930 | 1 × 375 = **375** | ~700 |

## Wall-clock estimate (per stage, single GPU, bs=2, Llama-3.2-1B)

Per-step time scales with attention work ~ O(L²). Estimates assume the
encoder is small relative to the LLM (which it is).

| Stage | Steps (3 ep, bs=2) | ~Per-step | Stage wall |
|---|---|---|---|
| AHRI pretrain | ~95k | 0.4 s | ~11 h |
| TSQA | ~57k | 0.3 s | ~5 h |
| HAR-CoT | ~103k | 0.3 s | ~9 h |
| Sleep-CoT | ~11k | 0.6 s | ~2 h |

Per-step estimates are pessimistic until we measure on real GPU. We
recalibrate at smoke-test time.

**Total per condition** (control and treatment run on separate GPUs in parallel):

| Run | Stages | Wall |
|---|---|---|
| Control | TSQA → HAR → Sleep | ~16 h |
| Treatment | AHRI → TSQA → HAR → Sleep | ~27 h |

Total wall ≈ **~1 day**, limited by treatment.

## Verdict rules

- **PROMISING** (write the paper): mean Δ > 1 pp **and** helps on ≥2/3 stages.
- **MILD POSITIVE** (replicate with 3 seeds): mean Δ > 0.5 pp OR helps on ≥2/3.
- **NULL** (reframe or shelve): no detectable effect; mean |Δ| < 0.5 pp.
- **HURTS** (investigate): mean Δ < -0.5 pp — AHRI is net negative.

A null result can still be a paper if the framing pivots to "Ahri as a
benchmark contribution" (CLEVR-style), but it's a weaker contribution.

## Caveats

1. **Single LLM scale** (Llama-3.2-1B). Multi-scale strengthens the claim.
2. **Single seed.** If Δ is marginal, repeat with 3 seeds before claiming.
3. **HAR/Sleep/ECG order is fixed.** Reordering could give different
   results due to task interference — could ablate in follow-up.
4. **Downstream data must be downloaded** (HAR-CoT and Sleep-CoT come from
   polybox URLs; ECG-QA-CoT requires PTB-XL + wfdb). The first run of each
   downstream stage will trigger the download.
